Offband 1.7.0 is the first stable release since **1.4.0** (2026-08-13). It supersedes the
`1.5.0-beta1`–`beta7` and `1.6.0-beta1` pre-release lines, neither of which reached a stable tag.
If you have been running stable, this one release carries three months of work.

Built on the **MeshCore 1.17.0** base.

## Read this before you upgrade

Four defaults changed. None of them breaks an existing install, but all four are visible.

- **The root default radio preset is now the US standard — 910.525 MHz, 62.5 kHz, SF7** (was
  869.618 MHz, SF8). This is the compiled-in default, so it reaches a node only when that node has
  no saved radio settings — a fresh flash, or one whose settings were erased. **An existing node
  keeps the settings it has.** The QCC badge is unaffected either way: it carries its own
  919.5 MHz / 500 kHz / SF7 variant setting.
- **Every role now defaults to 2-byte path hashes.** Previously each role set this for itself.
- **Channel notifications default to Self, and the Inherit scope is gone.** `Inherit` was a mode
  whose meaning depended on another setting; each channel now carries its own notification mode.
- **Diagnostic build filenames changed: `_testdiag` → `_diag`.** If you script downloads, update
  the pattern.

**Your settings, contacts and channels are preserved across the upgrade.** Stock MeshCore clients
and existing Offband clients keep working — see *Compatibility* below.

## New hardware

- **Queen City Con 0x4 badge** — a new board, with Offband messaging on it. Preflashed channels,
  a badge that names itself on first boot, single-button navigation, a message LED, buzzer and
  tunes, optional GPS, and a low-battery hold that recovers by itself. There is a
  [user guide](https://docs.offband.org/firmware/guides/qcc-badge/) with board diagrams for both
  the pyramid and supporter builds.
- **Heltec RadioCore RC52** (nRF52840) and **RC32** (ESP32-S3) — binaries published, displays
  brought up, GPS and strapping-pin hazards corrected.
- **Heltec Vision Master E290** — companion BLE and USB on the first e-ink board.
- **Heltec V4 TFT and V4-R8 TFT** — the color GUI boards. Images are published with releases.
- **SenseCAP T1000-E** — brought to parity: every sound through the shared tune engine, a send
  tone, GPS power save and the message-waiting LED.
- **ESP-NOW boards compile again**, and an ESP-NOW environment is in CI so the board class cannot
  rot unnoticed.

## The on-device GUI

The color touch boards now run a full Offband interface rather than a status screen.

- **Chats and channels** — compose with the on-screen keyboard, per-channel notifications, start a
  conversation from an empty Chats screen, add a channel as Public, hashtag or private, read a
  private channel's key and leave a channel from its menu.
- **Nodes** — the node list, with search by keyboard or letter wheel matching anywhere in the name.
- **Map** — a radar view.
- **Settings and boot** — settings persisted in flash, and the color Offband lockup on every color
  display.
- **Message store** — persisted to flash without stalling the interface.
- **SD card** — on the panel's SPI bus, with an archive that counts what it holds.
- **Sound** — Settings > Tones with a picker that auditions a tone before you keep it, custom
  tune slots, and per-channel tunes.
- **LVGL's memory moved to PSRAM**, so the interface stops filling internal RAM.

**The T-Deck GUI image is not published in this release.** The code is in and the environment
builds; the image is not shipped yet.

## Your client can now ask a device what it can do

Offband's own fields have left upstream's device-info frame and moved to a `0xC5 0x1C` capability
advert carrying tag / length / value records.

**Why this matters:** every Offband field used to be announced by incrementing *upstream's*
firmware version code. The moment upstream shipped a field of their own, the same number would mean
two different things and every deployed client's byte offsets would shift at once. Fields are now
found by tag, not by position.

Also reachable from a client, on a board with no keyboard:

- **GPS mode and power-save interval**, with capability bits to advertise them.
- **Custom RTTTL tune slots** — list, get, set and clear.
- **Per-channel tune.**
- **Display rotation** — correct a mounted or inverted screen from the client instead of
  reflashing. Hardware-verified on a QCC badge.

Capabilities are gated on the hardware that actually serves them, not on the board's name.

## Observer and repeater

- **CoreScope `/neighbors`** — a companion observer builds a zero-hop neighbor table from adverts,
  asks its neighbors for their regions one query at a time, and publishes the report to every
  broker without starving the heap that TLS needs.
- **A WiFi-telemetry repeater does the same** — it publishes its own scopes, and reports its
  neighbors' regions.
- **`discover.neighbors` and `discover.scopes`** console commands, with `mqtt.neighbors` settings,
  persistence and an `nbr:` status line.
- **Observer log forwarding to a syslog sink**, and the diagnostic log channel on nRF52 boards.
- **Broker rotation fixes** — rotated-out brokers no longer lose the traffic they missed, slot 0 is
  an always-on primary again, and normal rotation is no longer reported as a memory error.

## Reliability

- **A badge that refuses to boot now sleeps instead of boot-looping, and recovers by itself.** It
  shows an SOS and sleeps until it is charged or the button is pressed, and runs the cell down to
  3000 mV before refusing. Its GPS stays off while it waits.
- **ESP32 repeaters and companions arm the runtime watchdog.**
- **BLE transfers no longer lose 3 bytes per frame**, and framed serial writes are all-or-nothing.
- **A USB companion no longer streams fewer contacts than it declares.**
- **CrashLog can no longer block the boot it is diagnosing.**
- **A companion screen that fails to allocate now says so** instead of silently stopping all
  rendering.
- **Writing a channel over an occupied slot is refused** rather than silently destroying the
  channel that was there.
- **Public cannot be removed, always holds slot 0, and keeps its notification mode** when a channel
  is moved out of its way.
- **A negative or far-future clock is no longer treated as sane.**
- **An evicted pending ACK leaves a marker in the capture log** instead of looking like a lost
  packet.
- **A set Bluetooth PIN shows in full** instead of `******`, so you can read it in order to pair,
  and it is **drawn larger** on both badge kinds.
- **A long press into rescue mode now says so on screen.** It used to enter silently, which looked
  exactly like a hang.
- **Triple click backs out of a conversation** on a badge with no keyboard — there was previously
  no way back out.

## Known issues

- **A channel-slot rule the firmware cannot explain**
  ([#2025](https://github.com/OffbandMesh/meshcore-firmware/issues/2025)). Refusing a channel write
  over an occupied slot is new in this release and is the correct behavior, but the refusal does
  not tell you which slot is occupied or by what. Slots are also the wrong identifier for this.
  If a channel will not save, check whether its slot already holds one.

## Compatibility

- **Stock MeshCore clients and already-shipped Offband clients keep working.** The legacy fields
  are still emitted at their original offsets.
- **No released client asks for the `0xC5 0x1C` advert yet.** The current client
  (`meshcore-client` v1.7.0, 2026-10-27) predates it, so the new capability surfacing is available
  to clients that implement it, not to the one you have today.
- **Mixed meshes with stock MeshCore 1.18.0 are untested.** Offband rides the 1.17.0 base. Upstream
  tagged 1.18.0 on 2026-10-15; none of that code is in this line, and a mixed mesh has not been
  run on air.
