**Pre-release, for testers.** Six weeks and 119 commits since beta6. The app shows `1.5.0-beta7-1.17.0` once a device is upgraded.

### Take this build if you run an ESP32 node

Since #266 the `startWatchdog`/`feedWatchdog` calls sat inside `#if defined(NRF52_PLATFORM)` — so **no ESP32 repeater or companion has ever armed the task watchdog.** A hung main loop stayed hung until somebody reset the board by hand. Solar and rooftop nodes are where that hurts, because nobody is standing next to them.

**Cause:** the guard's original reason was bridge builds blocking >30 s on network calls. That no longer holds — MQTT runs in its own task and the loop's network calls time out in seconds.

**Now:** a hung main loop on any ESP32 board reboots within 30 s and reports `reset_reason=TASK_WDT`. nRF52 behaviour is unchanged. `WDT_TIMEOUT_SECS` (default 30) is the single build flag for an env that proves it needs longer. CI blocks the regression, and the guard sees through line continuations and same-file aliases.

Two new console verbs: `wdt status` answers from the board — whether arming actually succeeded — rather than from the build flag. `wdt hang` is diagnostic-only and never in a release image.

### USB companions

Three separate faults on `_usb` builds, all fixed:

- **Debug text in the protocol stream.** On a `_usb` companion, `Serial` *is* the framed companion protocol. Three paths wrote plain text into it, so a stock MeshCore client parsed one "unexpected frame type" per byte — settings rendered empty and the channel list never arrived.
- **Frames stalling on 64-byte boundaries.** A frame whose on-wire length was a multiple of the USB max packet size was held host-side until the next write. The terminator is now deferred, which keeps the non-blocking frame path non-blocking.
- **Console replies** gained the same zero-length terminator.

### WiFi config no longer lies about saving

`set wifi.ssid`, `set wifi.pwd` and `wifi enable`/`disable` discarded the NVS write result, so a failed write still returned the success acknowledgement. You were told the value was stored; it was silently gone after a reboot. `wifi clear all` also named only `pwd` when both keys failed to erase, so an operator could conclude the SSID was cleared while the node kept reconnecting to the old network.

### Observer log forwarding

Forwarding to a syslog sink is wired on all six observer envs. The sink is stored in NVS so it survives a reboot, a window can run until you switch it off, and the capture ring is read through a non-destructive cursor so forwarding never consumes what it forwards. An armed forward names a capture stop to the sink, so a reader can tell capture is off while the forward is still armed.

`caplog forward` no longer touches the WiFi link — arming used to overwrite whatever you had set with `wifi on`, and disarming tore the link down.

### Boot and shutdown reporting

Every reset is named, with why the board went down. The runtime is saved at shutdown. Previous-boot uptime and `rtc_count` report what they claim, and a previous-boot runtime recovered from NVS prints as a **floor** rather than presenting itself as a measurement.

### Queen City Con 0x4 badge

New board and standalone messaging on it: CardKB keyboard driving the UI, channel and DM sends with retries and an ACK tick when a repeater is heard passing a channel send on, a message store with conversations and unread counts, Messages as Home with inline compose, and Contacts / Nearby / Status / GPS / Settings on the SW1 cycle. Text size and screen-off are settings; the battery bar follows a measured lithium curve and learns the badge's own 100% from the charger settling.

Badge binaries publish with the release, diag build included.

**Under test.** The badge's Epic 2 verification (#1208) is still open, and with a GPS module fitted the badge holds it powered the whole time it is enabled — 2.5–3 days of battery against over a week without one. Duty cycling (#1288) is filed and is not in this build.

### Known issue, carried from beta6

**A USB companion can stream fewer contacts than it declares.** A RAK 4631 declared 350 and streamed 344–345 (#1279). `writeFrame` results go unchecked when the TX FIFO fills, so whole frames are dropped with nothing reported (#1283). Not a regression — present in beta6 — and the fix is in progress under #1298.

### Upgrade notes

- **RC32 diagnostic filenames changed: `_testdiag` → `_diag`.** If you pull RC32 diag builds, the names differ from beta4–beta6: `heltec_rc32_companion_radio_ble_diag`, `..._usb_diag`, `heltec_rc32_repeater_diag`.
- Release assets: 110 envs, up from 108 — the two new names are the QCC badge companion and its diag build.
- CI now builds every shipped RC32 and RCC6 env. Previously 15 shipped envs were compiled by nothing, so a change that broke either board merged green and surfaced only when a tag was cut.
