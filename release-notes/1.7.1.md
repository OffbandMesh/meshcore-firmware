Offband 1.7.1 is a patch release on top of **1.7.0** (2026-11-08). It fixes indicator control:
radios that reported display and LED control they could not honor, and a transmit LED that could
not be switched off on any board but two.

**Nothing else changed.** No default moved, no new board image is published, and the upgrade is an
ordinary one from 1.7.0. If you are coming from an older release, read the
[1.7.0 notes](https://github.com/OffbandMesh/meshcore-firmware/releases/tag/offband-v1.7.0) first —
the four changed defaults are described there.

Built on the **MeshCore 1.17.0** base.

## What was wrong

If you set the status LED off from a client and got *"the device doesn't support that"*, this
release is why it happened.

One capability flag answered two separate questions — can this board control its display, and can
it control its LED — and it was decided at compile time from whether a display class was present in
the build. Fifteen boards satisfy that test with a placeholder display driver that reports no
display at all. So those boards advertised both controls, your client offered both, and the write
was refused by the firmware that had just claimed to support it. It was reproduced on a Heltec
T096, a SenseCAP T1000-E and a QCC badge.

Separately, changing the display mode on a board with no screen was accepted, saved and read back
as though it had worked.

## What this release does

- **A radio reports display control and LED control separately, and only when it has them.** Both
  are now decided while the board is running — from whether a display actually came up, and whether
  the board can drive its LED — rather than from how the firmware was compiled. A board can report
  one without the other.
- **A display change on a screenless board is refused**, rather than saved and echoed back.
- **The transmit and heartbeat LED can be switched off on boards where it previously could not.**
  Sixty-three boards have a transmit LED; two of them honored the setting. The state now lives in
  the shared board code, so most of the fleet gains it at once — including sixteen nRF52 boards with
  a heartbeat LED, among them the **SenseCAP T1000-E**, the **RAK4631**, the **ThinkNode** boards
  and the **XIAO nRF52**. Verified on hardware on a T1000-E.
- **A board that cannot control its LED now says the LED is on**, whatever you asked, because the
  LED is working normally. "I can't switch this" is not the same answer as "it's off".
- **The Queen City Con badge keeps its LED behavior on purpose.** It is the one deliberate
  exception, and it is declared in the badge's own board configuration rather than hidden in shared
  code.

## Still to come

Some boards drive their LED from their own transmit code rather than through the shared path, and
on those the switch does not take effect yet. That is tracked as
[#2075](https://github.com/OffbandMesh/meshcore-firmware/issues/2075) and is not in this release.

## Compatibility

- **Upgrading from 1.7.0 keeps your settings, contacts and channels.**
- **Older radios still work with a new client.** The original single capability flag is kept as the
  coarse answer for firmware released before this one, so a client that understands the new
  per-indicator records still reads an older radio correctly. Where the new records are present,
  they are what counts.
- **Stock MeshCore clients are unaffected.** No byte upstream reads has changed.
- A client has to ask for the new records to use them. Until your client does, it falls back to the
  single flag, which behaves exactly as it did in 1.7.0.

## Images

The published image set is unchanged from 1.7.0. T-Deck Pro work in this release is diagnostic only
and ships no image.
