📻 **Offband firmware v1.7.0** is out — **stable**, and the first stable release since 1.4.0 back in August. It supersedes the whole 1.5.0 and 1.6.0 beta line. If you've been running stable, this one build carries three months of work.

🖥️ **The color boards run a real interface now.** Chats and channels with the on-screen keyboard, a Nodes list you can search, a Map radar view, persisted settings, a message store that writes to flash without stalling the UI, SD card support, and Settings > Tones with a picker that auditions a tone before you keep it. LVGL's memory moved to PSRAM, so the GUI stops eating internal RAM. Heltec V4 TFT and V4-R8 TFT images ship with the release. **The T-Deck GUI image is not published yet** — the code's in and the env builds, but it isn't shipped.

⌨️ **The Queen City Con 0x4 badge is done being "under test."** It names itself `QCC-` + the last four of its BLE MAC on first boot, so a table of fresh badges isn't a table of identical names. It holds preflashed channels, plays tunes through the buzzer, and when the battery is too low to run it, it shows an SOS and sleeps until you charge it instead of boot-looping — then starts again by itself, down to a 3000 mV cutoff. Full guide with board diagrams for both the pyramid and supporter builds: https://docs.offband.org/firmware/guides/qcc-badge/

🔑 **Pairing and the one button, if your badge has no keyboard.** The Bluetooth PIN **shows in full and is drawn larger** — it used to render as `******`, which made it impossible to read in order to pair. The button walks the lists on the main screens, picking a screen first and then moving through it; **triple click backs out of a conversation**; and **a long press into rescue mode now says so on screen** instead of entering silently, which used to be indistinguishable from a hang. You can also set a channel's notification mode on the badge itself, not just from the client.

🔌 **Your client can ask a device what it supports instead of counting bytes.** Offband's fields have moved out of upstream's device-info frame into a `0xC5 0x1C` capability advert with tag/length/value records. The old way announced our fields by bumping *upstream's* version code — the day upstream shipped a field of their own, every deployed client's offsets would have shifted at once. **Nothing breaks today:** the legacy bytes are still emitted where they always were, so stock MeshCore clients and your current Offband client work exactly as before. The current client doesn't ask for the advert yet, so this is groundwork you'll see land client-side.

📡 **Observers and repeaters report who they can hear.** A zero-hop neighbor table built from adverts, neighbors queried for their regions one at a time, and the result published to CoreScope's `/neighbors` without starving the heap TLS needs. `discover.neighbors` and `discover.scopes` on the console. Repeaters with WiFi telemetry do it too, for their own scopes and their neighbors'.

🔊 **T1000-E parity.** Every sound goes through the shared tune engine, plus a send tone, GPS power save and the message-waiting LED.

📶 **Default radio preset changed: 910.525 MHz / 62.5 kHz / SF7** (was 869.618 / SF8). This is the compiled-in default, so it only applies to a **fresh flash or a node whose settings were erased** — an existing node keeps what it has. QCC badges are unaffected; they carry their own 919.5 / 500 kHz / SF7.

⚠️ **Known issue:** writing a channel into an occupied slot is now correctly refused, but the refusal doesn't tell you which slot is taken or by what. If a channel won't save, check whether its slot already holds one.

📚 **There's a manual now:** https://docs.offband.org/firmware/ — installing and updating, observer MQTT and what the brokers can see, SafeBoot and recovery, the badge, and the T1000-E.
